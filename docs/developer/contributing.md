# Contributing

CopyRoom uses the family contract in the repository's `AGENTS.md`. Use the
devenv shell for Python commands. Use gitman for repository history and publish
completed changes through the current gitman lane.

## Code rules

- Keep CLI handlers thin. Put project state changes in `local/` modules.
- Render and validate the complete output plan before changing a project.
- Use one owner for each output path. Check collisions before creating a layer
  or preview.
- Run jj with argument lists and preserve its exit status and output.
- Keep provider calls behind explicit `generate` or `refresh` commands.
- Store generated bytes before they enter an ordinary update path.
- Write short active sentences and use CopyRoom's fixed vocabulary.

## Change map

| Change | Main module |
| --- | --- |
| Render validation and output paths | `local/composer.py` |
| Source snapshots and markers | `local/source.py` |
| jj workspaces and locks | `local/jj.py` |
| Project create, update, and recovery | `local/workflow.py` |
| Explicit model generation | `local/generation.py` |
| Adoption and source extraction | `local/manage.py` |
| Workshop registry and candidate flow | `local/workshop.py` |
| Public commands | `cli.py` |

## Before publish

Run pytest, Ruff, and the walkthrough in the root devenv shell. Run a fresh
consumer shell when changing the Nix module or Python package. Inspect the
whole active worktree before you describe and publish the gitman change. Do not
add attribution lines to commit messages.
