# Path ownership preflight spike

Date: 2026-10-07

## Question

Can a manifest reject exact and file-directory path collisions before `new`, layer add, update, and generated refresh? Can an overlay keep a conditional seed omitted on later updates?

## Method

Run [spike.py](spike.py) with the pinned jj environment from spike 12:

```bash
cd .scratch/projects/12-jj-render-merge
devenv shell -- bash -c 'export PATH="$DEVENV_PROFILE/bin"; python3 ../21-path-ownership/spike.py'
```

The script builds staged file trees outside a disposable jj project. A small preflight reads each staged tree's file paths. It compares every owner's proposed paths before it writes project files or calls jj. The project marker records current owner paths and the overlay's omitted seed path. [evidence.json](evidence.json) records each check and rejected collision.

The final run passed 45 checks and rejected nine collisions. Ruff passed.

## Findings

- Initial `new` rejected both an exact collision and a file-directory collision before it created a project repository.
- Layer add rejected an exact collision with the base layer and a child path beneath a base-owned file.
- Base update rejected an overlay-owned path and a file at an overlay-owned directory prefix. A separate base update with disjoint paths succeeded.
- Generated refresh rejected a base-owned file and a file at an overlay-owned directory prefix. A later refresh replaced the prior generated bytes and kept its own path.
- The overlay source included a `config.toml` seed. The first overlay render omitted it because the base layer owned that path. The project marker saved the omission. A later raw overlay update failed preflight when it tried to add the seed. Applying the saved omission allowed other overlay files to update while the base kept `config.toml`.
- Every rejected action against the existing project kept both the active jj `@` commit and the full project file fingerprint unchanged.

## Rule

Build a manifest from the **effective rendered output** of every layer and generated snapshot. Before a change, replace only the changing owner's manifest in a proposed manifest set. Reject equal paths and file-directory prefixes across owners. Keep conditional seed omissions in project state and apply them to each later render. Run this preflight before project files or jj state change.

The omission is a stable ownership decision. If a project wants to transfer the path later, it needs an explicit ownership change; a new template render must not claim it by accident.

## Limits

This is a preflight model, not a patch to CopyRoom or prototype 13. The staged trees use fixed text fixtures rather than a Templateer render. The test checks rejection ordering and jj state in a disposable repo. It does not test filesystem failures after preflight, concurrent changes, symlinks, case-insensitive filesystems, or an explicit ownership transfer. The earlier [jj merge spike](../12-jj-render-merge/SPIKE.md) proves why shared paths are unsafe in the proposed render-commit graph.
