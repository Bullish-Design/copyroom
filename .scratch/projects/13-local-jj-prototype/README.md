# Local jj prototype

This prototype tests local `new` and `update` with one template layer. It does
not replace CopyRoom. Run its tests from the pinned spike environment:

```bash
cd .scratch/projects/12-jj-render-merge
devenv test
```

Run the commands in a disposable directory with that shell:

```bash
devenv shell -- python3 ../13-local-jj-prototype/prototype.py new \
  --template fixtures/base-v1 --target /tmp/my-test-project \
  --answers fixtures/answers.json
devenv shell -- python3 ../13-local-jj-prototype/prototype.py update \
  --project /tmp/my-test-project --template fixtures/base-v2
```

The project marker stores the local template path, answers, generated paths,
and a render fingerprint. It stores no render commit ID. Each render commit
contains a project ID in its description. The update command finds the latest
marked render ancestor, makes the next render its child, checks the merge base,
and merges it with the project commit.

`--generated DIR` is optional. Supply a local snapshot from an explicit LLM
run. The command copies those bytes into the render commit before the merge.
An update without `--generated` reuses the last committed generated bytes. The
prototype never calls a model by itself.

The renderer supports scalar `{{ answer }}` substitutions in UTF-8 text and
path segments. It rejects path escapes, output collisions, symlinks, and
reserved paths. The generated snapshot can contain binary files.

The prototype calls jj directly inside its target repo. Gitman does not expose
the render branch and merge operations yet. Use the prototype only in
disposable repos. It supports one layer and no remote template sources.
